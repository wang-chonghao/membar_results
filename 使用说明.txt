A5 Membar 实验结果汇总

查看结果
--------
完整克隆或下载本仓库后，用浏览器打开 spill_candidate_alignment_summary.html。
该页面统一展示原 CAModel、VfSim 全局/局部与软件优化结果，包含 32 个算子/子 VF 分组、92 行。
主表保留 55 个含 Vector/Predicate/Scalar spill 的版本和 37 个无 spill 基线。
全部 153 个成功原版本保存在 metadata/spill_candidate_all_versions.json。
24 个 VF stack 超限版本单独记录，不进入表格、图表、CSV 和性能统计。
39 个软件入选方案保留数值和无 compiler spill 验证；未预测或未优化项明确留空。
页面顶部可筛选算子、来源、spill 状态；点击 Case 查看实际 CCE，点击证据查看详情。
软件性能指同 shape、算术、名义 unroll 的软件改写方案在全局 Membar 下的 VfSim 预测性能，
通过循环切分、指令重排降低活跃值并避免 compiler spill；不是 CAModel 或预测程序运行耗时。
“Membar / 软件性能” = VfSim 软件优化全局周期 / VfSim 局部周期 × 100%；
100% 持平，大于 100% 表示局部依赖更快，缺失数据不计算。无 spill 基线沿用原版本。
spill_candidate_alignment_summary.md 包含统计口径、字段解释和与 HTML 一致的完整汇总表。
本次整理不改变已归档周期、IPC 或预测参数。历史模型和跨版本比较限制在详情中保留。
仅核验数据与文件 SHA256，不需要 CANN 或 VfSimulator：
  python3 scripts/validate_spill_candidate_archive.py
图表、数据、源码和日志均在仓库内，离线也能查看。
Git 已禁用自动换行转换，以保留原始日志及源码的字节校验一致性。
查看结果不需要安装 Python、CANN 或 VfSimulator，也不需要启动服务器。
新增 A6 专题：打开 a6_softmax_fusion_results_summary.html，查看 FP16 Softmax
三循环与 SUM→NORM 两行错位融合在 8/12/16/24/32 行下的历史预测、UB 占用及 IPC。
A6 专题没有 A6 CAModel 实测；32 行完整 buffer 超出 248KiB 预算，只用于趋势比较。
各版本 CCE、结果、警告和图表均归档在 a6_softmax_fp16_row_scaling/ 内，离线可查看。
A6 完整运行入口另见 a6_softmax_fp16_row_scaling/runnable_a6/README.md；
提供 8×1024 的 NDDMA/scatter wrapper、显式同步对照及独立 FP16 golden。
历史 source/kernel.cce 仍是 VF-only 快照，不作为 host kernel 入口。
请保留整个目录；只下载 HTML 文件会缺少数据和图表资源。
GitHub 的文件页面显示 HTML 源码，下载后的 HTML 才是可交互报告。

CAModel 用例复现
---------------
运行环境：Linux 或 WSL 的 Bash，Python 3.11 或更新版本，以及带对应模拟器的 CANN。
原实验使用 CANN 9.0.0-beta.1、Ascend950PR_9599、dav-c310-vec。
CAModel 运行入口只依赖 Python 标准库和 CANN，不需要安装 VfSimulator。

1. 配置新机器的环境

编辑结果根目录的 set_env.sh，通常只需要确认下面四项：
  export MEMBAR_CANN_ROOT="/你的CANN安装目录"
  export MEMBAR_HOST_ARCH="x86_64-linux"
  export MEMBAR_NPU_TYPE="Ascend950PR_9599"
  export MEMBAR_CORE_ARCH="dav-c310-vec"

MEMBAR_CANN_ROOT 是包含 CANN 自身 set_env.sh 的安装目录。
MEMBAR_HOST_ARCH 是主机架构；普通 Intel/AMD Linux 或 WSL 使用 x86_64-linux。
MEMBAR_NPU_TYPE 是模拟芯片型号，MEMBAR_CORE_ARCH 是匹配的 CCE 编译目标。
更换型号或编译目标必须得到当前 CANN 的支持，也可能改变编译后的指令与周期。

下面两组配置通常保持空字符串，无需填写：
  MEMBAR_CXX_INCLUDE_DIRS、MEMBAR_EXTRA_LIBRARY_DIRS：额外头文件/库目录。
  仅在标准安装位置无法找到依赖时使用；多个目录按冒号分隔，例如 /opt/include1:/opt/include2。
  MEMBAR_CCEC、MEMBAR_HOST_CXX、MEMBAR_LINKER：指定自定义编译器或链接器。
  留空时自动从 MEMBAR_CANN_ROOT 下查找 ccec、bisheng 和 ld.lld。

修改后，在结果根目录加载这一份配置：
  cd /你的路径/membar_results
  source ./set_env.sh

set_env.sh 会加载 CANN 环境，并设置编译目标、模拟型号和运行库路径。
不需要再加载各 case 的历史 run_output/run_simexec_env.sh；它们保留原始环境记录。

2. 运行 SwiGLU Grad U6

在已经 source set_env.sh 的同一个终端中执行：
  python3 swiglu_grad/u6/camodel_case/run.py --out-dir /tmp/swiglu_grad_u6_run1

脚本按顺序编译 host、编译 CCE、链接 kernel、执行 CAModel，然后对两个输出做 golden 校验。
成功时终端显示 "passed": true。输出目录必须为空或尚不存在，并位于归档目录之外。
再次运行时换一个目录名，例如 /tmp/swiglu_grad_u6_run2。

Windows E 盘上的当前目录，在 WSL 中可以直接运行：
  cd /mnt/e/VfSimulator/results/membar_results
  source ./set_env.sh
  python3 swiglu_grad/u6/camodel_case/run.py --out-dir /tmp/swiglu_grad_u6_run1

输出文件位于 /tmp/swiglu_grad_u6_run1：
  validation.json：两个输出的 golden 精度校验结果。
  host_build.log、compile.log、link.log：构建日志，构建失败时查看相应文件。
  camodel.log：CAModel 运行日志。
  core0.veccore0.instr_log.dump、core0.veccore0.instr_popped_log.dump：指令流水日志。
  input*.bin、output*.bin、golden*.bin：本次执行的输入、输出与 golden。

查看 VF 周期：
  grep 'vf_execute_time' /tmp/swiglu_grad_u6_run1/core0.veccore0.instr_log.dump
该 U6 版本的历史 CAModel 时间为 3281 cycles；重跑时以新日志为准。

3. 只查看命令或检查历史精度

查看将执行的构建与运行命令，不进行编译或仿真：
  python3 swiglu_grad/u6/camodel_case/run.py --dry-run
只核验已保存的输出与 golden，不需要 CANN，也不需要 source set_env.sh：
  python3 swiglu_grad/u6/camodel_case/run.py --check-archived
同一终端里运行其他 case 时，替换 run.py 路径即可；无需重新修改环境配置。
--toolkit <CANN目录> 可单次覆盖集中配置中的 CANN 路径。

归档材料说明
------------
每个版本的 camodel_case/README.txt 和 case.json 说明材料来源、运行入口和缺失项。
FlashAttention Grad 的原临时目录仍在，已复制 CAModel 用例材料；较早实验从仓库保留材料恢复，
原编译产物缺失时明确标记。Softmax 旧版本没有保存 input/output/golden 数据，
其历史精度证据保留在原报告中；重跑时由 host 重新生成输入和 golden。
run_output/ 保存历史运行材料；original_scripts/ 保留原实验脚本及历史路径。
独立 run.py 使用用例内的源码和 host，不依赖 VfSimulator 预测 API。
进入任一 camodel_case/ 后，也可从该目录加载集中配置并运行：
  source ../../../set_env.sh
  python3 run.py --dry-run
  python3 run.py --check-archived
  python3 run.py --out-dir /tmp/自定义重跑目录
本次补齐为材料归档，没有重新运行 CAModel，也没有刷新表中的周期或 IPC。
metadata/camodel_cases.json 为各版本材料完整性清单。
归档不保留 sim_history.json 或 sim_history.json.gz 这类 VfSim 详细调试历史。
这些文件不是 CAModel 运行或 IPC 报告的依赖；本机归档与远程仓最新版本均已移除。
CAModel 原始日志、输入输出、golden、源码与构建入口保留，IPC 使用的精简日志也保留。

FlashAttention Grad 前段新增 7 个版本，包含集中加载 U2 的 compiler spill、
原序直接 U2、生命周期重排与三个 bank-aware 预取窗口。
228 cycle 为重排后 CAModel 实测；306 cycle 为保留 spill 的局部依赖假设性预测。
228/306 约为 74.51%，只是跨口径的耗时数值比较，不是已验证的硬件加速比。
同指令流的模型内同步收益比较为全局 3208 / 局部 306，约 10.48 倍。

MHC Sinkhorn 收录 8、36、64、128 矩阵共 19 个版本，目录及页面 ID 统一为 mhc_sinkhorn。
历史结果保存在 metadata/data.json；在统一汇总页中按 MHC 算子及 shape 筛选。
各形状包含 UB、驻留 U1/U2/U4 和 element-major；36 矩阵另有驻留 U6。
hc_mult=4，4x4 FP32，20 轮；全部 CAModel 都通过数值与保护区校验。
UB 全局/局部预测分别为 13202/5202、57050/22721、100898/40320，收益约 2.54/2.51/2.50 倍。
驻留 U6 保留 457 条 spill store、570 条 spill load、1064 条动态 membar，预测为 29007/24349。
U6 提供实际日志还原的硬件等效 CCE；预测使用对应 CanonicalVfInfo，并非重新编译这份说明用 CCE。
8/36/64 的 element-major CAModel 为 2146/2425/2760；新校准预测 Python/C++ 均为 2586。
精度分别为 79.50% / 93.36% / 93.70%，动态 PC 与寄存器依赖均核查通过。
这三个版本无 mem_bar；已替代原未运行/无有效预测的页面记录。
36 矩阵已补跑局部依赖预测：2586 cycle，与全局相同，模型内加速 1.00 倍。
局部实验为 Python 32B RAW/WAR/WAW，49 条访存全部解析且核查通过；未移除任何屏障。
8/64 矩阵局部结果仍未运行。C++ 只核对全局预测，局部不是优化硬件实测。
当前固定 GSU 时序仍不随有效 lane 数变化，因此 8 矩阵偏差较大，并非指令遗漏。
8/36/64 新 element-major 与 128 使用相同配置校验值，部分 forwarding/II 的 fallback warning 保留。
128 矩阵 element-major U1：CAModel 4950，全局预测 5082，精度 97.33%，未跑局部预测。
128 矩阵 element-major U2：CAModel 11446，全局预测 11118，精度 97.13%，局部预测 4145。
128 矩阵 4+15 切分＋重排：CAModel 4600，全局预测 Python/C++ 4364，精度 94.87%，局部预测 4327。
切分版无自动向量/谓词 spill，仅 1 条 mem_bar；显式 scratch 8KiB，保存/读回各 32 次。
scratch 复用预留 result 空间，公共 UB 布局仍为 30976B；输出与原 U1 逐字节一致，保护区通过。
全局与局部来自同一编译后日志输入，2946 条指令的 PC、寄存器依赖核查通过；162 条访存全部解析。
局部只少 37 cycle，加速约 1.009 倍，为 Python 假设性硬件实验，不是 CAModel 实测。
对应 CCE、两份 CAModel 日志、参数快照及预测日志已归档到 m128_element_major_split4_15。
U2 同流局部模型内收益 2.68 倍，保留 234 次向量保存、234 次重载和原有 468 条 membar 的证据。
局部预测用 32B RAW/WAR/WAW 替代全局 membar，550 条访存全部解析，依赖核查通过。
U2 提供按实际日志还原、包含 spill 的等效 CCE；该说明代码未重新编译，预测使用对应 CanonicalVfInfo。
128 两版本输入、golden、输出逐字节相同，2048 个有效输出及保护区校验通过。
全局预测 Python/C++ 一致；局部为 Python 实验，未声称 C++ 已同步或优化硬件已经实测。
Element-major 使用新校准的全 64 lane 稀疏 GSU 参数；历史 8/36/64 UB / 驻留版周期保持原样，不能混作同一参数版本。
VGATHER2.b32 latency=35、GSU interval=16；VSCATTER.b32 latency=43、interval=32。
公共 UB 布局均为 30976B（30.25KiB），不含 VF 栈；默认 IPC 仍为 8 矩阵 UB，100-cycle 窗口。
MHC 的计算完成 IPC 已排除 Gather/Scatter 访存；修正统计口径，不改变周期或模型参数。
64 矩阵 element-major 的原 AscendC 为 2797 cycle，对应 CCE 为 2760，并非周期完全对齐。
8 矩阵为早期固定形状实现，36/64 为通用形状；输入样本跨形状不完全相同。
这是提取 VF 的测试，不能称为完整 MHC 算子的时间；局部结果不是优化硬件的实测周期。

发生 spill 的版本中的 source/hardware_equivalent.cce 是实际底层硬件 VF 计算、
UB 访存及同步指令流的等效表达，已补入寄存器溢出引入的保存、重载和 mem_bar。
源文件注释和 PC 映射记录给出了还原范围；标量地址计算效果折入指针及立即数。

辅助脚本
--------
以下两个工具只依赖 Python 标准库，可在独立结果仓库中运行：
  python scripts/validate_archive.py
  python scripts/prepare_hardware_equivalent.py

其余脚本需要另外提供 VfSimulator 仓库路径，不再固定本机磁盘地址：
  python scripts/validate_hardware_cce.py --vfsim-root <VfSimulator路径>
  python scripts/verify_gelu_hardware_numerics.py --vfsim-root <VfSimulator路径>
  python scripts/build_archive.py --vfsim-root <VfSimulator路径>
  python scripts/add_flash_attention_grad_front.py --vfsim-root <VfSimulator路径>
  python scripts/add_mhc_sinkhorn.py --vfsim-root <VfSimulator路径>
  python scripts/bundle_camodel_cases.py --vfsim-root <VfSimulator路径>

add_flash_attention_grad_front.py 只更新该 case，不重建其余历史实验。
add_mhc_sinkhorn.py 保留已有 UB / 驻留数据，增量更新新校准 element-major 结果并迁移旧 MHC 目录名。
bundle_camodel_cases.py 按 manifest 的原始日志来源补齐用例目录，并核对材料与报告日志一致。

build_archive.py 和数值核查需要原实验数据；这些数据不是打开报告的依赖。
数值核查还需要 NumPy，前端核查需要 VfSimulator 自身的 Python 依赖。
无需为了查看已有结果而运行生成脚本。
